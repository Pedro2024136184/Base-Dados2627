Bases de Dados: Exercício 1 — Identificação de Veículos

Unidade Curricular: Bases de Dados • Modelo: Notação de Chen e Regras de Transformação

Enunciado:
Num sistema de identificação de veículos, um proprietário pode possuir mais do que um veículo e um veículo pode ser propriedade de mais do que um proprietário. Os veículos são identificados pela respetiva matrícula e são caracterizados pela marca, modelo e cor. Os proprietários são identificados pelo número de contribuinte e possuem ainda nome, morada, data de nascimento e sexo. Os veículos possuem obrigatoriamente um só motor o qual é identificado pelo número de motor e é caracterizado ainda pela cilindrada e tipo de combustível.

1. Identificação de Entidades, Atributos e Chaves

Entidade Chave Primária (PK) Atributos Descritivos Descrição / Papel
Proprietario NIF (Número de Contribuinte) Nome, Morada, Data_Nascimento, Sexo Pessoa individual registada no sistema.
Veiculo Matricula Marca, Modelo, Cor Veículo automóvel registado.
Motor Numero_Motor Cilindrada, Tipo_Combustivel Unidade de propulsão associada obrigatoriamente a um veículo.

5. Justificação Teórica com Referências aos Acetatos da Cadeira

1. Relação Veículo – Motor (Grau 1:1 e Participação Obrigatória de Veículo):
• Acetato: (BD2627)T02_ER_Part1.pdf • Diapositivo 16 / Slide 32: Caso 2 (1:1) – Regra 2.
• Regra 2 da Teórica: «São necessárias duas tabelas, uma para cada entidade; A chave primária de cada entidade serve de chave primária na tabela correspondente; A chave primária da entidade com participação não obrigatória tem de ser usada como atributo na tabela correspondente à entidade cuja participação é obrigatória.»
• Aplicação: Dado que o enunciado impõe que «Os veículos possuem obrigatoriamente um só motor», a chave primária de Motor (Numero_Motor) passa para a tabela Veiculo como chave forasteira com restrição NOT NULL (assegura obrigatoriedade) e UNIQUE (assegura o grau 1:1 sem valores nulos).

2. Relação Proprietário – Veículo (Grau M:N):
• Acetato: (BD2627)T02_ER_Part1.pdf • Diapositivo 25 / Slide 50: Regra 6 – Grau M:N.
• Regra 6 da Teórica: «São sempre necessárias três tabelas, uma para cada entidade e uma terceira para o relacionamento; A chave própria de cada entidade serve de chave primária na tabela correspondente; A tabela relativa ao relacionamento terá de ter entre os atributos da sua chave primária, as chaves primárias de cada uma das entidades.»
• Aplicação: Um proprietário pode possuir vários veículos e um veículo pode ter múltiplos proprietários (compropriedade). Cria-se obrigatoriamente a tabela de relacionamento Proprietario_Veiculo com chave primária composta (NIF, Matricula).

6. Implementação SQL (DDL)

CREATE TABLE Motor (
    Numero_Motor VARCHAR(50) PRIMARY KEY,
    Cilindrada INT NOT NULL,
    Tipo_Combustivel VARCHAR(30) NOT NULL
);

CREATE TABLE Veiculo (
    Matricula VARCHAR(20) PRIMARY KEY,
    Marca VARCHAR(50) NOT NULL,
    Modelo VARCHAR(50) NOT NULL,
    Cor VARCHAR(30) NOT NULL,
    Numero_Motor VARCHAR(50) NOT NULL UNIQUE,
    CONSTRAINT FK_Veiculo_Motor FOREIGN KEY (Numero_Motor) 
        REFERENCES Motor(Numero_Motor)
);

CREATE TABLE Proprietario (
    NIF VARCHAR(9) PRIMARY KEY,
    Nome VARCHAR(100) NOT NULL,
    Morada VARCHAR(255) NOT NULL,
    Data_Nascimento DATE NOT NULL,
    Sexo CHAR(1) CHECK (Sexo IN ('M', 'F', 'O'))
);

CREATE TABLE Proprietario_Veiculo (
    NIF VARCHAR(9) NOT NULL,
    Matricula VARCHAR(20) NOT NULL,
    PRIMARY KEY (NIF, Matricula),
    CONSTRAINT FK_PV_Proprietario FOREIGN KEY (NIF) REFERENCES Proprietario(NIF),
    CONSTRAINT FK_PV_Veiculo FOREIGN KEY (Matricula) REFERENCES Veiculo(Matricula)
);

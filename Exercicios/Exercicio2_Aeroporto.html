Bases de Dados: Exercício 2 — Gestão de Aviação num Aeroporto

Unidade Curricular: Bases de Dados • Modelo: Notação de Chen e Regras de Transformação

Enunciado:
Num aeroporto pretende implementar-se uma base de dados destinada a registar elementos referentes às diversas companhias de aviação que nele operam.
• A sigla da companhia, composta por 3 letras de valor único (ex.: TAP, VAR, LFH), nome completo único, número de aviões ao serviço.
• Cidades em que a companhia tem escritórios (supõe-se 1 escritório por cidade), direção (rua e número) do escritório e o país a que cada cidade pertence.
• Os voos efetuados: cada voo identificado por sigla única de 2 letras e 3 algarismos (ex.: TP474), efetuado por apenas uma companhia.
• Cada voo tem uma cidade de origem, uma cidade destino e cidades em que faz escala (podendo não fazer nenhuma escala). A mesma cidade pode ser escala de vários voos.
• Para cada voo e cidade de escala, regista-se o tempo de permanência no solo.

1. Identificação de Entidades, Atributos e Relacionamentos

A. Entidades

Entidade Chave Primária (PK) Atributos Descritivos Descrição
Companhia Sigla_Companhia (CHAR(3)) Nome_Companhia (Único), Num_Avioes Empresa de aviação comercial que opera no aeroporto.
Voo Sigla_Voo (CHAR(5), ex: TP474) (Informações adicionais do voo) Ligação aérea operada por uma dada companhia.
Cidade Nome_Cidade (VARCHAR) Pais Localidade geográfica de origem, destino, escala ou escritório.

B. Relacionamentos

Relacionamento Entidades Envolvidas Grau Participação Atributos do Relacionamento
Efetua Companhia (1) – Voo (N) 1 : N Voo: Obrigatória (linha dupla) • Companhia: Opcional Nenhum
Origem Cidade (1) – Voo (N) 1 : N Voo: Obrigatória (linha dupla) • Cidade: Opcional Nenhum
Destino Cidade (1) – Voo (N) 1 : N Voo: Obrigatória (linha dupla) • Cidade: Opcional Nenhum
Tem_Escritorio Companhia (M) – Cidade (N) M : N Ambas opcionais (0..N) Direcao (rua e número)
Escala Voo (M) – Cidade (N) M : N Ambas opcionais (voo pode não ter escalas) Tempo_Solo (tempo de permanência)

5. Justificação Teórica com Base nas Regras da Cadeira

1. Relacionamentos Binários 1:N com Participação Obrigatória do lado N (Regra 4):
• Acetato: (BD2627)T02_ER_Part1.pdf • Diapositivo 21 / Slide 42: Caso 1 (1:N) – Regra 4.
• Regra 4: «São necessárias duas tabelas, uma para cada entidade; A chave primária de cada entidade serve de chave primária na tabela correspondente; A chave primária da entidade do lado 1 tem de ser usada como atributo na tabela correspondente à entidade do lado N.»
• Aplicação a Efetua (Companhia – Voo): Como cada voo é operado obrigatoriamente por 1 companhia, Sigla_Companhia passa como chave forasteira para a tabela Voo.
• Aplicação a Origem e Destino (Cidade – Voo): Cada voo tem obrigatoriamente 1 cidade de origem e 1 cidade de destino. As chaves de Cidade migram como chaves forasteiras Cidade_Origem e Cidade_Destino na tabela Voo (ambas com restrição NOT NULL).

2. Relacionamentos Binários M:N com Atributos Próprios (Regra 6):
• Acetato: (BD2627)T02_ER_Part1.pdf • Diapositivo 25 / Slide 50: Regra 6 – Grau M:N.
• Regra 6: «São sempre necessárias três tabelas, uma para cada entidade e uma terceira para o relacionamento; A chave própria de cada entidade serve de chave primária na tabela correspondente; A tabela relativa ao relacionamento terá de ter entre os atributos da sua chave primária, as chaves primárias de cada uma das entidades.»
• Aplicação a Tem_Escritorio: Uma companhia pode ter escritórios em várias cidades e numa cidade podem existir escritórios de várias companhias. Cria-se a tabela Escritorio com chave primária composta (Sigla_Companhia, Nome_Cidade) e o atributo descritivo Direcao.
• Aplicação a Escala: Um voo pode fazer escala em múltiplas cidades e uma cidade pode ser escala de vários voos. Cria-se a tabela Voo_Escala com chave primária composta (Sigla_Voo, Nome_Cidade) e o atributo descritivo Tempo_Solo.

6. Implementação SQL (DDL)

-- 1. Tabela CIDADE
CREATE TABLE Cidade (
    Nome_Cidade VARCHAR(100) PRIMARY KEY,
    Pais VARCHAR(80) NOT NULL
);

-- 2. Tabela COMPANHIA
CREATE TABLE Companhia (
    Sigla_Companhia CHAR(3) PRIMARY KEY,
    Nome_Companhia VARCHAR(120) NOT NULL UNIQUE,
    Num_Avioes INT NOT NULL CHECK (Num_Avioes >= 0)
);

-- 3. Tabela VOO (1:N com Companhia, Origem e Destino)
CREATE TABLE Voo (
    Sigla_Voo CHAR(5) PRIMARY KEY, -- ex: TP474
    Sigla_Companhia CHAR(3) NOT NULL,
    Cidade_Origem VARCHAR(100) NOT NULL,
    Cidade_Destino VARCHAR(100) NOT NULL,
    CONSTRAINT FK_Voo_Companhia FOREIGN KEY (Sigla_Companhia) REFERENCES Companhia(Sigla_Companhia),
    CONSTRAINT FK_Voo_Origem FOREIGN KEY (Cidade_Origem) REFERENCES Cidade(Nome_Cidade),
    CONSTRAINT FK_Voo_Destino FOREIGN KEY (Cidade_Destino) REFERENCES Cidade(Nome_Cidade),
    CONSTRAINT CK_Origem_Destino CHECK (Cidade_Origem <> Cidade_Destino)
);

-- 4. Tabela de Relacionamento ESCRITORIO (M:N entre Companhia e Cidade)
CREATE TABLE Escritorio (
    Sigla_Companhia CHAR(3) NOT NULL,
    Nome_Cidade VARCHAR(100) NOT NULL,
    Direcao VARCHAR(200) NOT NULL, -- Rua e número
    PRIMARY KEY (Sigla_Companhia, Nome_Cidade),
    CONSTRAINT FK_Escritorio_Companhia FOREIGN KEY (Sigla_Companhia) REFERENCES Companhia(Sigla_Companhia),
    CONSTRAINT FK_Escritorio_Cidade FOREIGN KEY (Nome_Cidade) REFERENCES Cidade(Nome_Cidade)
);

-- 5. Tabela de Relacionamento VOO_ESCALA (M:N entre Voo e Cidade)
CREATE TABLE Voo_Escala (
    Sigla_Voo CHAR(5) NOT NULL,
    Nome_Cidade VARCHAR(100) NOT NULL,
    Tempo_Solo INT NOT NULL CHECK (Tempo_Solo > 0), -- em minutos
    PRIMARY KEY (Sigla_Voo, Nome_Cidade),
    CONSTRAINT FK_Escala_Voo FOREIGN KEY (Sigla_Voo) REFERENCES Voo(Sigla_Voo),
    CONSTRAINT FK_Escala_Cidade FOREIGN KEY (Nome_Cidade) REFERENCES Cidade(Nome_Cidade)
);

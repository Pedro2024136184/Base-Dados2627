1. Estrutura e Ordem de Execução de uma Query

O maior erro dos alunos nos testes é pensar que o SQL executa pela ordem com que é escrito. O Oracle compila e processa os blocos numa ordem lógica muito específica.

Ordem de Escrita no Código Ordem de Execução pelo Motor Oracle O que faz nesta fase?
1. SELECT [DISTINCT] 3. WHERE Filtra linhas individuais antes de agrupar. Proibido usar agregados!
2. FROM ... JOIN ... ON 1. FROM + JOIN Carrega as tabelas e faz os cruzamentos/junções relacionais.
3. WHERE 2. ON (do JOIN) Aplica os critérios de junção entre chaves primárias e forasteiras.
4. GROUP BY 4. GROUP BY Condensa as linhas individuais em grupos com base nas colunas dadas.
5. HAVING 5. HAVING Filtra os grupos com base nos cálculos de grupo (COUNT, SUM).
6. ORDER BY 6. SELECT Projeta as colunas pedidas e atribui os aliases (AS "...").
- 7. ORDER BY Ordena a apresentação final das linhas resultantes.
⚠️ Consequência direta na Correção dos Testes: Como o SELECT só executa no Passo 6, o Oracle não conhece aliases no WHERE, nem no GROUP BY, nem no HAVING! Usar aliases aí dá de imediato o erro ORA-00904: invalid identifier. Apenas o ORDER BY permite aliases.

2. Linguagem de Manipulação de Dados (DML)

A matéria de DML cobre a inserção, modificação e eliminação de tuplos. Nos testes do ISEC, estas perguntas exigem quase sempre o uso de subqueries.

A. O Comando INSERT

Adiciona novas linhas a uma tabela. Pode ser feito por valores explícitos ou a partir do resultado de um SELECT.

-- 1. Inserção simples com listagem explícita de colunas
INSERT INTO dep (ndep, nome, loc)
VALUES (50, 'DESENVOLV', 'DETROIT');

-- 2. Inserção com valores Nulos e Datas (SYSDATE ou TO_DATE)
INSERT INTO emp (nemp, nome, funcao, encar, data_entrada, sal, premios, ndep)
VALUES (7196, 'GREEN', 'VENDEDOR', 7782, SYSDATE, 2000, NULL, 10);

-- 3. Inserção a partir de um SELECT (SEM a palavra VALUES!)
-- Exemplo clássico do slide TP10: copiar linhas de uma tabela para outra
INSERT INTO gestores (id, nome, salario, data_entrada)
SELECT nemp, nome, sal, data_entrada
FROM   emp
WHERE  funcao = 'GESTOR';

-- 4. Inserção com agregação dinâmica (Exemplo do Teste 2023/24 - Pergunta 5)
INSERT INTO INVOICE (idInvoice, invoiceDate, fromDate, toDate, value, idContract)
SELECT 77865,
       SYSDATE,
       TO_DATE('01-11-2023', 'DD-MM-YYYY'),
       TO_DATE('30-11-2023', 'DD-MM-YYYY'),
       NVL(SUM(pc.cost), 0),
       9
FROM PHONE p
JOIN PHONECALL pc ON p.idPhone = pc.idPhone
WHERE p.idContract = 9
  AND TO_CHAR(pc.callDate, 'MM-YYYY') = '11-2023';

B. O Comando UPDATE

Modifica valores de registos existentes. Se omitires o WHERE, atualiza todas as linhas da tabela.

-- 1. Atualização simples com filtro
UPDATE emp
SET    ndep = 20, sal = sal * 1.10
WHERE  nemp = 7782;

-- 2. Atualização com Subquery de Várias Colunas (Slide TP10)
-- Atualiza a função e o departamento do 7698 para serem iguais aos do 7499
UPDATE emp
SET    (funcao, ndep) = (
    SELECT funcao, ndep
    FROM   emp
    WHERE  nemp = 7499
)
WHERE  nemp = 7698;

-- 3. Atualização correlacionada baseada noutra tabela
-- Atualiza o saldo ou resultado após evento de jogo (Teste 2015/16)
UPDATE JOGO
SET    n_golos_visitante = n_golos_visitante + 1
WHERE  idjogo = 4256;

C. O Comando DELETE

Remove linhas existentes da tabela. Sujeito a restrições de integridade referencial.

-- 1. Eliminação simples de linhas específicas
DELETE FROM dep
WHERE nome = 'DESENV';

-- 2. Eliminação baseada em Subquery noutra tabela (Slide TP10)
DELETE FROM emp
WHERE ndep = (
    SELECT ndep
    FROM   dep d
    WHERE  d.nome = 'VENDAS'
);

-- 3. Exemplo Real de Teste (Exame 2019/2020 - Pergunta 4)
-- Banir jogador 'LandLord' anulando ataques efetuados (idPlayer1) e sofridos (idPlayer2)
DELETE FROM PLAYERATTACK
WHERE idBattle IN (
    SELECT idBattle
    FROM   BATTLE
    WHERE  UPPER(location) = 'SOUTH BAY'
)
AND (
    idPlayer1 = (SELECT idPlayer FROM PLAYER WHERE UPPER(username) = 'LANDLORD')
    OR
    idPlayer2 = (SELECT idPlayer FROM PLAYER WHERE UPPER(username) = 'LANDLORD')
);
⚠️ Erros de Integridade DML que tens de saber reconhecer:
  • ORA-02291: integrity constraint violated - parent key not found: Tentaste inserir ou atualizar uma Foreign Key com um valor que não existe na tabela mãe.
  • ORA-02292: integrity constraint violated - child record found: Tentaste fazer DELETE ou alterar uma Primary Key na tabela mãe que tem registos filhos a apontar para ela.

3. Linguagem de Definição de Dados (DDL) & Restrições

O teste avalia a capacidade de construir esquemas relacionais íntegros e seguros através de CREATE TABLE e ALTER TABLE.

A. Tipos de Dados Fundamentais no Oracle

Tipo de DadoDescriçãoExemplo Prático
NUMBER(p, s)Numérico. p=precisão total de dígitos, s=casas decimais.NUMBER(7,2) (até 99999.99) ou NUMBER(4)
VARCHAR2(tamanho)Texto de tamanho variável (até 4000 caracteres).VARCHAR2(100)
CHAR(tamanho)Texto de tamanho fixo preenchido com espaços.CHAR(1) (ex: género 'M'/'F')
DATEData e hora (século, ano, mês, dia, hora, minuto, segundo).DATE (ex: '2023-12-13 14:30:00')

B. Molde Oficial de CREATE TABLE com Restrições (Vale 20%)

Regra da Prof.ª Fernanda: Dar sempre nomes explícitos com prefixos padrão (pk_, fk_, ck_, uk_).

CREATE TABLE INVOICE (
    idInvoice    NUMBER,
    invoiceDate  DATE        DEFAULT SYSDATE,
    fromDate     DATE        NOT NULL,
    toDate       DATE        NOT NULL,
    value        NUMBER(8,2) NOT NULL,
    idContract   NUMBER      NOT NULL,

    -- 1. Chave Primária
    CONSTRAINT pk_invoice PRIMARY KEY (idInvoice),

    -- 2. Chave Forasteira (ligação à tabela mãe CONTRACT)
    CONSTRAINT fk_invoice_contract FOREIGN KEY (idContract) 
        REFERENCES CONTRACT (idContract) /* ON DELETE CASCADE */,

    -- 3. Restrições CHECK (valores não negativos e coerência temporal)
    CONSTRAINT ck_invoice_value CHECK (value >= 0),
    CONSTRAINT ck_invoice_dates CHECK (toDate > fromDate),
    CONSTRAINT ck_invoice_invdate CHECK (invoiceDate > toDate)
);
💡 O que o CHECK NÃO PERMITE (Pergunta de Teórica/Prática):
  • Não permite chamadas a funções variáveis como SYSDATE, USER ou UID.
  • Não permite subconsultas (SELECT ...) nem referenciar colunas de outras tabelas.
  • Não permite pseudocolunas como ROWNUM ou CURRVAL.

C. O Comando ALTER TABLE

Quando as tabelas foram criadas sem restrições ou precisam de ser alteradas posteriormente (como no Teste 2019/20 - Pergunta 5):

-- Adicionar múltiplas constraints de uma só vez (OBRIGATÓRIO USAR PARÊNTESES no Oracle!)
ALTER TABLE BATTLE ADD (
    CONSTRAINT pk_battle_id     PRIMARY KEY (idBattle),
    CONSTRAINT fk_battle_clan1  FOREIGN KEY (idClan1) REFERENCES CLAN (idClan),
    CONSTRAINT fk_battle_clan2  FOREIGN KEY (idClan2) REFERENCES CLAN (idClan),
    CONSTRAINT ck_battle_prize  CHECK (coinsPrize > 0)
);

-- Adicionar NOT NULL (usa-se MODIFY e não ADD)
ALTER TABLE emp MODIFY (sal NUMBER(7,2) NOT NULL);

-- Remover ou desativar uma restrição
ALTER TABLE dep DROP CONSTRAINT dep_ndep_pk CASCADE;
ALTER TABLE emp DISABLE CONSTRAINT emp_ndep_fk;

D. Criação de Vistas (CREATE VIEW)

Aparece em testes quando se pede para encapsular uma consulta analítica complexa (Exemplo do Teste 2015/16 - Pergunta 6):

CREATE OR REPLACE VIEW V_CLASSIFICA AS
SELECT competicao AS "COMPETICAO",
       equipa     AS "EQUIPA",
       SUM(pontos) AS "N_PONTOS"
FROM (
    -- Vitórias em Casa (3 pontos)
    SELECT j.competicao, eq.nome AS equipa, 3 AS pontos
    FROM JOGO j JOIN EQUIPA eq ON j.id_eq_visitada = eq.id_equipa
    WHERE j.n_golos_visitado > j.n_golos_visitante
    UNION ALL
    -- Vitórias Fora (3 pontos)
    SELECT j.competicao, eq.nome AS equipa, 3 AS pontos
    FROM JOGO j JOIN EQUIPA eq ON j.id_eq_visitante = eq.id_equipa
    WHERE j.n_golos_visitante > j.n_golos_visitado
)
GROUP BY competicao, equipa
ORDER BY competicao, "N_PONTOS" DESC;

4. Junções de Tabelas (JOINs)

Dominar a ligação entre tabelas é essencial para qualquer consulta relacional.

Tipo de JunçãoSintaxe Oracle PadrãoComportamento
INNER JOINFROM T1 JOIN T2 ON T1.id = T2.idApenas linhas que têm correspondência em ambas as tabelas.
LEFT OUTER JOINFROM T1 LEFT JOIN T2 ON T1.id = T2.idTodas as linhas de T1 + correspondências de T2 (preenche com NULL se não houver).
FULL OUTER JOINFROM T1 FULL JOIN T2 ON T1.id = T2.idTodas as linhas de ambas as tabelas, com NULLs nos pares sem par.
SELF JOIN (Auto-junção)FROM PLAYER ME JOIN PLAYER P ON ...A tabela junta-se consigo mesma usando aliases diferentes (atacante vs atacado).
 
-- Auto-Junção Real (Teste 2019/20 - Pergunta 1)
-- O jogador 'Scar Face' lutou contra outro jogador (P) da mesma região
SELECT p_adv_clan.name AS "Clã Adversário",
       b.location      AS "Local da batalha",
       b.battleDate    AS "Data da batalha"
FROM BATTLE b
JOIN PLAYERATTACK pa ON b.idBattle = pa.idBattle
JOIN PLAYER me       ON (pa.idPlayer1 = me.idPlayer OR pa.idPlayer2 = me.idPlayer)
JOIN PLAYER p_adv    ON (pa.idPlayer1 = p_adv.idPlayer OR pa.idPlayer2 = p_adv.idPlayer)
JOIN CLAN p_adv_clan ON p_adv.idClan = p_adv_clan.idClan
WHERE UPPER(me.username) = 'SCAR FACE'
  AND me.idPlayer != p_adv.idPlayer
  AND p_adv.region = me.region
  AND TO_CHAR(b.battleDate, 'YYYY') = '2019'
ORDER BY b.battleDate DESC;

5. Agregações & GROUP BY / HAVING

As funções de grupo operam sobre conjuntos de linhas para produzir um único resultado por grupo.

As 5 Funções de Grupo Fundamentais

  • COUNT(*): Conta todas as linhas resultantes (incluindo nulos).
  • COUNT(coluna): Conta apenas linhas onde a coluna não é nula.
  • COUNT(DISTINCT coluna): Conta valores únicos sem repetições.
  • SUM(coluna): Soma os valores (ignora nulos; dá NULL se o grupo estiver vazio).
  • AVG(coluna): Média aritmética (ignora nulos).
  • MAX(coluna) / MIN(coluna): Maior e menor valor (numérico, texto ou data).

Regras Inquebráveis de Exame

1. Regra de Ouro do SELECT vs GROUP BY: Se usares funções agregadas, todas as outras colunas que estejam no SELECT têm obrigatoriamente de estar no GROUP BY. Caso contrário: ORA-00937: not a single-group group function.
2. Regra de Ouro do WHERE vs HAVING: WHERE filtra linhas individuais (antes do agrupamento). HAVING filtra os grupos resultantes. Nunca coloques COUNT ou SUM dentro do WHERE! 
-- Exemplo Canónico (Teste 2023/24 - Pergunta 2)
SELECT c.name                          AS "Nome Cliente",
       TO_CHAR(pc.callDate, 'YYYY-MM') AS "ANO_MES",
       COUNT(*)                        AS "NUM_CHAMADAS",
       SUM(pc.duration)                AS "NUM_TOTAL_MINUTOS"
FROM CONTRACT c
JOIN PHONE p       ON c.idContract = p.idContract
JOIN PHONECALL pc  ON p.idPhone = pc.idPhone
WHERE TO_CHAR(c.startDate, 'YYYY') = '2022'
  AND TO_CHAR(pc.callDate, 'YYYY') = '2022'
  AND pc.duration > 2
GROUP BY c.name, TO_CHAR(pc.callDate, 'YYYY-MM')
HAVING COUNT(*) >= 5 
   AND SUM(pc.duration) >= 100
ORDER BY "NUM_CHAMADAS" DESC, "NUM_TOTAL_MINUTOS" ASC;

6. Subconsultas & A Receita do "Top 1 / Máximo por Grupo"

Subconsultas são consultas aninhadas dentro de outro comando SQL. Podem devolver um único valor (escalar), uma lista de valores (múltiplas linhas) ou múltiplas colunas.

A. Operadores de Múltiplas Linhas: IN, ANY, ALL

  • IN: Igual a qualquer elemento da lista devolvida.
  • > ALL (...): Maior do que todos os elementos (isto é, maior que o máximo da lista).
  • <= ALL (...): Menor ou igual a todos os elementos (isto é, o menor/mínimo da lista).
  • > ANY (...): Maior do que pelo menos um dos elementos (isto é, maior que o mínimo da lista).

B. A Receita de Ouro do ISEC: "O Maior de Cada Grupo" (>= ALL)

Aparece em quase todos os testes (ex: "destino com mais chamadas", "melhor marcador de cada equipa", "livro mais vendido por editora").

📋 Memoriza esta Receita Universal: 
SELECT GrupoA, DetalheB
FROM   Tabelas
WHERE  Filtros_Gerais
GROUP BY GrupoA, DetalheB
HAVING COUNT(*) >= ALL (
    -- Subquery que calcula as contagens DESTE MESMO grupo GrupoA
    SELECT COUNT(*)
    FROM   Tabelas_Sub
    WHERE  Tabelas_Sub.GrupoA = Tabelas.GrupoA /* Correlação com o pai! */
      AND  Filtros_Gerais
    GROUP BY Tabelas_Sub.DetalheB
);
-- Exemplo Aplicado Real: Melhor Marcador de Cada Equipa (Teste 2015/16 - Pergunta 4)
SELECT eq.nome   AS "EQUIPA",
       jog.nome  AS "NOME"
FROM EQUIPA eq
JOIN JOGADOR jog ON eq.id_equipa = jog.id_equipa
JOIN EVENTO ev   ON jog.id_jogador = ev.id_jogador
WHERE UPPER(ev.tipo_evento) = 'GOLO'
GROUP BY eq.id_equipa, eq.nome, jog.id_jogador, jog.nome
HAVING COUNT(*) >= ALL (
    SELECT COUNT(*)
    FROM JOGADOR jog2
    JOIN EVENTO ev2 ON jog2.id_jogador = ev2.id_jogador
    WHERE jog2.id_equipa = eq.id_equipa -- Mesmo clube
      AND UPPER(ev2.tipo_evento) = 'GOLO'
    GROUP BY jog2.id_jogador
);

7. Funções de Linha (Datas, Texto, Conversão e NVL)

Operam sobre valores individuais de cada linha. Essenciais nos filtros do WHERE e na formatação das projeções do SELECT.

A. A Função Salvador: NVL

Substitui valores NULL por um valor predefinido. Lembrete: Qualquer operação aritmética com NULL resulta em NULL!

-- Salário total: se comissao for NULL, soma 0 em vez de anular o salário
SELECT nome, sal + NVL(comissao, 0) AS "Total Recebido" FROM emp;

-- Em agregações para tabelas externas que possam não ter linhas:
NVL(SUM(pc.cost), 0)

B. Manipulação de Datas em Oracle

Necessidade de ExameSintaxe Correta OracleO que NÃO fazer (Erros)
Data atual do sistemaSYSDATENOW() ou CURRENT_DATE() (MySQL)
Filtrar por Ano (ex: 2022)TO_CHAR(data, 'YYYY') = '2022'Comparar strings sem converter
Filtrar por Mês e AnoTO_CHAR(data, 'MM-YYYY') = '11-2023'Comparar apenas o mês e esquecer o ano
Horas do dia (ex: após as 20h)TO_CHAR(data, 'HH24') >= '20'Tentar usar funções não standard
Primeiro dia do mês passadoTRUNC(ADD_MONTHS(SYSDATE, -1), 'MM')Subtrair 30 dias
Último dia do mês passadoLAST_DAY(ADD_MONTHS(SYSDATE, -1))Assumir sempre 30 ou 31 dias

C. Texto e Strings

  • UPPER(campo) / LOWER(campo): Converte para maiúsculas/minúsculas. Obrigatório quando o enunciado diz que os textos não têm formato padronizado.
  • LIKE '%COIMBRA%': Procura padrões. % representa 0 ou mais caracteres; _ representa exatamente 1 caractere.
  • SUBSTR(string, inicio, tamanho): Extrai parte de um texto.
  • INSTR(string, padrao): Devolve a posição numérica onde o padrão ocorre.

8. Controlo de Transações (TCL)

Uma transação SQL é uma unidade lógica de trabalho composta por um conjunto de instruções DML executadas sequencialmente.

ComandoEfeito na Base de Dados
COMMIT;Grava permanentemente todas as alterações pendentes da sessão no disco. Torna as alterações visíveis aos outros utilizadores e liberta bloqueios de linhas.
ROLLBACK;Descarta todas as alterações pendentes, restaurando a base de dados para o estado do último COMMIT.
SAVEPOINT nome;Cria um ponto de salvaguarda intermediário dentro da transação em curso.
ROLLBACK TO nome;Reverte as alterações feitas apenas após o ponto de salvaguarda indicado, mantendo as anteriores ativas.
📌 Commit Implícito em Oracle: Sempre que executas qualquer instrução DDL (CREATE, ALTER, DROP, TRUNCATE), o Oracle efetua automaticamente um COMMIT implícito antes e depois da instrução!

9. Banco de Casos Reais: Resoluções de Testes Anteriores

Caso 1: Teste 2023/2024 — Pergunta 1 (Junções + Strings + Subquery IN)

Enunciado: Clientes residentes em Coimbra com contrato que ligaram para o José Gonçalves no mês passado com chamadas > 2 min.

SELECT c.name             AS "Nome Cliente",
       c.nif              AS "Nif",
       p.phoneNumber      AS "PHONENUMBER",
       pc.destPhoneNumber AS "DESTPHONENUMBER"
FROM contract c
JOIN phone p       ON c.idContract = p.idContract
JOIN phonecall pc  ON p.idPhone = pc.idPhone
WHERE UPPER(c.address) LIKE '%COIMBRA%'
  AND pc.duration > 2
  AND TO_CHAR(pc.callDate, 'MM-YYYY') = '11-2023'
  AND pc.destPhoneNumber IN (
      SELECT p2.phoneNumber
      FROM phone p2
      JOIN contract c2 ON p2.idContract = c2.idContract
      WHERE UPPER(c2.name) = 'JOSÉ GONÇALVES'
  )
ORDER BY c.name ASC;

Caso 2: Teste 2019/2020 — Pergunta 3 (Subquery de Dano Mínimo Sofrido)

Enunciado: Qual o jogador do clã 'The Vikings' em que o total de dano sofrido (healthRemoved) na batalha de 'Joshua Hill' foi menor?

SELECT pl.username AS "Nome do Jogador"
FROM PLAYER pl
JOIN CLAN c          ON pl.idClan = c.idClan
JOIN PLAYERATTACK pa ON pl.idPlayer = pa.idPlayer2 -- idPlayer2 = atacado/sofreu
JOIN BATTLE b        ON pa.idBattle = b.idBattle
WHERE UPPER(c.name) = 'THE VIKINGS'
  AND UPPER(b.location) = 'JOSHUA HILL'
GROUP BY pl.idPlayer, pl.username
HAVING SUM(pa.healthRemoved) <= ALL (
    SELECT SUM(pa2.healthRemoved)
    FROM PLAYER pl2
    JOIN CLAN c2          ON pl2.idClan = c2.idClan
    JOIN PLAYERATTACK pa2 ON pl2.idPlayer = pa2.idPlayer2
    JOIN BATTLE b2        ON pa2.idBattle = b2.idBattle
    WHERE UPPER(c2.name) = 'THE VIKINGS'
      AND UPPER(b2.location) = 'JOSHUA HILL'
    GROUP BY pl2.idPlayer
);

Caso 3: Teste 2015/2016 — Pergunta 1 (CREATE TABLE com Restrições)

Enunciado: Crie a tabela EVENTO com PK, FKs e restrição de minuto_jogo não negativo.

CREATE TABLE EVENTO (
    id_evento    NUMBER,
    id_jogo      NUMBER        NOT NULL,
    id_jogador   NUMBER        NOT NULL,
    minuto_jogo  NUMBER        NOT NULL,
    tipo_evento  VARCHAR2(30)  NOT NULL,
    comentario   VARCHAR2(200),

    CONSTRAINT pk_evento          PRIMARY KEY (id_evento),
    CONSTRAINT fk_evento_jogo     FOREIGN KEY (id_jogo) REFERENCES JOGO (idjogo),

    CONSTRAINT ck_evento_minuto   CHECK (minuto_jogo >= 0)
);

10. Checklist de Exame: Os 10 Mandamentos do ISEC

🚨 O Que a Professora Desconta Automaticamente:
  1. Esquecer o UPPER/LOWER: Se comparas texto puro sem UPPER() quando o enunciado avisa que não há formato, descontas logo.
  2. Aspas Erradas: Aspas simples '...' são apenas para texto/datas literais. Aspas duplas "..." são apenas para cabeçalhos de colunas (aliases).
  3. Agregações no WHERE: Nunca coloques COUNT() ou SUM() dentro do WHERE. O sítio das agregações é no HAVING.
  4. Coluna fora do GROUP BY: Qualquer coluna no SELECT que não seja agregação tem de ir para o GROUP BY.
  5. Aliases no WHERE / GROUP BY: Nunca uses os nomes criados com AS "..." dentro de filtros ou agrupamentos. Repete a expressão completa.
  6. Nomes das Restrições: Em DDL, nunca cries constraints sem nome. Usa sempre CONSTRAINT pk_..., CONSTRAINT fk_..., etc.
  7. Parênteses em Constraints: Escrever PRIMARY KEY id em vez de PRIMARY KEY (id) dá erro imediato de compilação.
  8. A Palavra REFERENCES: Em chaves forasteiras escreve-se REFERENCES tabela (coluna) e nunca ON tabela.coluna.
  9. Proteção contra Nulos: Em faturas, cálculos ou somas que possam vir vazias, aplica sempre NVL(SUM(...), 0).
  10. Inversão de Lógica Booleana: "Excluir se A < 5 OU B < 100" significa no HAVING: A >= 5 AND B >= 100 (Lei de De Morgan).
